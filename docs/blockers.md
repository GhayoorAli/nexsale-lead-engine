# Blockers – things only you can do

Everything below was built and tested with `MOCK_EXTERNAL=true` (all external APIs served by `tests/mock_server`).
The live tests (Level 3 integration and Level 4 end-to-end against real services) need these steps first.
All keys go into `.env` only (never into workflow JSON). Keep `DEMO_MODE=true` and `TEST_LEAD_LIMIT=10`.

| # | What | Why it blocks | Exact steps |
|---|------|---------------|-------------|
| 1 | **Test inboxes + allowlist** | Guard blocks every send while the allowlist is empty | Create 2 Gmail accounts (sender, test prospect). In `.env`: `SENDER_EMAIL=…`, `TEST_PROSPECT_EMAIL=…`, `TEST_RECIPIENT_ALLOWLIST=<sender>,<prospect>`, `TEST_LEAD_LIMIT=10`, `AUTO_REPLY_MIN_CONFIDENCE=0.85`. |
| 2 | **Start n8n + fixed tunnel** | Slack buttons, Calendly and the forms need one public URL that never changes | One time: sign up free at ngrok.com → **Your Authtoken** → copy it; **Domains** → claim the free static domain. In `.env`: `NGROK_AUTHTOKEN=…`, `NGROK_DOMAIN=<name>.ngrok-free.app`, `COMPOSE_PROFILES=tunnel`, `WEBHOOK_URL=http://localhost:5678/` (n8n's own address; the tunnel only forwards Slack clicks). Then `docker compose up -d` starts n8n and the tunnel together. Open the campaign form at http://localhost:5678/form/campaign-setup. Set the Slack Request URL once to `https://<NGROK_DOMAIN>/webhook/slack-actions`. (Quick `cloudflared` tunnels get a new random URL each start and can expire mid-demo.) |
| 3 | **n8n API key** | Deploy script and tests use the public API | n8n → Settings → n8n API → Create API key → `.env`: `N8N_API_KEY=`. Then `python setup/deploy_workflows.py` (imports/updates all 19 workflows and activates them). |
| 4 | **Airtable** | Database for everything | Start the 14-day Team trial (~10 days before the interview). Create an empty base "Nexsale Lead Engine". Create a personal access token with scopes `data.records:read`, `data.records:write`, `schema.bases:read`, `schema.bases:write` for that base. `.env`: `AIRTABLE_PAT=`, `AIRTABLE_BASE_ID=app…`. Run `python setup/create_airtable_base.py` (creates 9 tables; safe to run twice), then `python setup/seed_test_data.py --no-replies` (adds the client "Real Service GmbH"). Optional by hand: autonumber fields `client_id`, `campaign_id`, `lead_id`, … (the Meta API can't create autonumber fields; the workflows don't need them). |
| 5 | **Airtable Interface (dashboard + list)** | Interfaces can't be created by API | In the base: Interfaces → New → Dashboard. Add number/progress elements from Campaigns (`leads_sourced`, `enriched_pct`, `emails_sent`, `reply_rate_pct`, `positive_replies`, `meetings_booked`, `meetings_held`, `cost_per_lead_eur`, `cost_per_meeting_eur`) and Clients (`positive_pct`, `meetings_pct` as progress bars vs 20 / 4). Add a "Leads" list page filtered by campaign. Copy the Interface URL into `.env` as `AIRTABLE_INTERFACE_URL=` (it becomes the "Open full list" button). |
| 6 | **Google Places API (New)** | Sourcing | Google Cloud: new project → enable "Places API (New)" → billing account → API key restricted to Places API (New) → **budget alert €5** and **quota 200 requests/day**. `.env`: `GOOGLE_MAPS_API_KEY=`. Then capture one real response: `python setup/capture_places_fixture.py` (1 request, 10 Berlin cleaning companies) – it overwrites `tests/fixtures/google_places_berlin_10.json`. |
| 7 | **AI key** | Emails, sorting, summaries | OpenAI: create key → `.env`: `AI_PROVIDER=openai`, `AI_MODEL=gpt-4o-mini`, `OPENAI_API_KEY=`. (Or `AI_PROVIDER=anthropic`, `ANTHROPIC_API_KEY=`, `AI_MODEL=<model>`.) |
| 8 | **Gmail OAuth credential in n8n** | Sending and the reply trigger | n8n → Credentials → New → "Gmail OAuth2 API" → sign in with the **sender** account → name it `Gmail sender`. Open `13_send_email` → node "Send via Gmail" → select the credential. Do the same in `05_campaign_launch` → "Gmail profile" and `07a_gmail_inbox` → "New mail in sender inbox". Activate `07a_gmail_inbox`. |
| 9 | **Slack app** | Notifications and the 3rd click | api.slack.com/apps → Create app → Bot scopes `chat:write`, `chat:write.public` → install to workspace → `.env`: `SLACK_BOT_TOKEN=xoxb-…`, `SLACK_CHANNEL=#leads`. Basic information → Signing secret → `SLACK_SIGNING_SECRET=`. Incoming Webhooks → on → add to #leads → `SLACK_WEBHOOK_URL=` (used by the error handler). Interactivity → on → Request URL `<WEBHOOK_URL>/webhook/slack-actions`. Invite the bot to #leads. |
| 10 | **Calendly** | Booking webhook | One 15-minute event → `.env`: `CALENDLY_LINK=` and in Airtable Clients.calendly_link. Personal access token → `CALENDLY_TOKEN=`. Create the webhook subscription (needs a paid plan or trial – if this fails, use the trial or Cal.com): `curl -X POST https://api.calendly.com/webhook_subscriptions -H "Authorization: Bearer $CALENDLY_TOKEN" -H "Content-Type: application/json" -d '{"url":"<WEBHOOK_URL>/webhook/calendly","events":["invitee.created","invitee.canceled"],"organization":"<org uri>","scope":"organization","signing_key":"<random>"}'` and put the signing key in `.env` as `CALENDLY_WEBHOOK_SIGNING_KEY=`. |
| 11 | **HubSpot** | CRM sync | Free CRM → Settings → Integrations → Private apps → scopes `crm.objects.contacts.read/write`, `crm.objects.companies.read/write`, `crm.objects.deals.read/write` → `.env`: `HUBSPOT_TOKEN=`. Optional: your owner id into Clients.hubspot_owner_id. |
| 12 | **Screen recording + rehearsal** | Phase 10 deliverable | Run the demo script (`docs/demo_script.md`) twice and record it as backup. |
| 13 | **Real data fixtures (optional but planned)** | PLAN.md wants real pages | After step 6, run one test campaign of 10 real Berlin companies and keep it as demo data. To replace the synthetic Impressum fixtures, save 10 of their public Impressum pages into `tests/fixtures/impressum/` and update `expected.json` by hand. |

After 1–11: `python tests/integration/run_integration.py` (Level 3) and `python tests/e2e/run_e2e.py --live` twice (Level 4).
